# ZippyPair Tools

Production-ready Next.js 15 App Router application for a SaaS-style online tools directory. The codebase is organized into a clear `src/app`, `src/frontend`, and `src/backend` architecture.

## Stack

- Next.js 15 App Router
- React 19
- TypeScript
- Tailwind CSS v4
- shadcn/ui primitives
- Lucide React icons
- Prisma 7
- PDF, image, media, AI, calculator, conversion, security, text, SEO, social, and file utility services

## Scripts

```bash
npm run dev
npm run build
npm run start
npm run typecheck
```

Notes:

- `npm run build` runs `prisma generate` before `next build`.
- There is currently no `lint` script or local ESLint setup.
- On Windows PowerShell, use `npm.cmd` if script execution policy blocks `npm`.

## Architecture Rules

- `src/app` contains only Next.js routing files: pages, layouts, global styles, route handlers, and route-specific shells.
- `src/frontend` contains reusable UI, frontend data, hooks, constants, and frontend-only utilities.
- `src/backend` contains server-side request handling, controllers, services, repositories, middleware, validators, database clients, workers, storage, queues, and backend types.
- API route handlers in `src/app/api` must stay thin. They should import a backend controller and delegate the request.
- Business logic should live in `src/backend/services` or `src/backend/tools`, not in `src/app`.
- Request parsing and validation should live in `src/backend/controllers`, `src/backend/utils`, and `src/backend/validators`.

Example API route pattern:

```ts
import { mergePdfController } from "@/backend/controllers/pdf/merge.controller";

export const runtime = "nodejs";
export const dynamic = "force-dynamic";

export async function POST(request: Request) {
  return mergePdfController(request);
}
```

## Backend

`src/backend` owns all server-side behavior.

```text

  queue/
  repositories/
  services/
  storage/

  types/
  utils/
  validators/
```

### `src/backend/controllers`

Controllers adapt HTTP requests to services. They parse request data, call validators, invoke services, and return responses.

| Folder/File | Purpose | Usage |
| --- | --- | --- |
| `ai/*.controller.ts` | Controllers for AI tools: grammar, paraphrase, plagiarism, summarize, text-to-speech, translate. | Add one controller per AI endpoint. |
| `calculators/calculation.controller.ts` | Generic calculation tool controller for dynamic and shared calculator routes. | Use when tool behavior comes from `backend/tools/calculation-tools.ts`. |
| `calculators/currency.controller.ts` | Currency calculator request wrapper. | Uses calculator validator and service. |
| `calculators/nepali-date.controller.ts` | Nepali date converter request wrapper. | Uses calculator validator and service. |
| `health/health.controller.ts` | Health endpoint response. | Keeps `/api/health` route thin. |
| `pdf/*.controller.ts` | PDF endpoint controllers for merge, split, compress, conversions, and page removal. | Add PDF request orchestration here, not in `app/api`. |

### `src/backend/database`

Database/client access layer. Clients should use lazy initialization so builds do not crash when runtime env vars are missing.

| File | Purpose | Usage |
| --- | --- | --- |
| `prisma.ts` | Lazy Prisma client using `DATABASE_URL`. | Import `getPrisma()` or `prisma` for Prisma-backed repositories/services. |
| `postgres.ts` | Lazy `pg` pool using `DATABASE_URL`. | Use for raw PostgreSQL queries when Prisma is not appropriate. |
| `redis.ts` | Redis-like cache abstraction with in-memory fallback. | Use for cache/session/rate-limit style storage until a real Redis adapter is wired. |

### `src/backend/lib`

Backend-specific integration helpers.

| File | Purpose | Usage |
| --- | --- | --- |
| `groq.ts` | Lazy Groq/LangChain chat model wrapper. | AI services call `runGroqChat`. Requires `GROQ_API_KEY`. |
| `upload.ts` | File upload constants, validation, filename sanitizing, buffers, base64 conversion, multipart checks. | Used by validators, controllers, and PDF services. |

### `src/backend/middleware`

Reusable backend middleware-style helpers. These are not Next.js `middleware.ts`; they are server utilities used by controllers/services.

| File | Purpose | Usage |
| --- | --- | --- |
| `Auth.ts` | Authorization header assertion. | Use in controllers that require auth. |
| `Logger.ts` | Builds request log entries. | Use when adding structured request logging. |
| `RateLimit.ts` | In-memory rate limit assertion. | Use for lightweight endpoint throttling. |
| `Upload.ts` | Multipart upload assertion wrapper. | Use before processing upload endpoints. |

### `src/backend/queue`

| File | Purpose | Usage |
| --- | --- | --- |
| `index.ts` | In-memory queue types and queue class. | Use as a simple queue abstraction for later durable queue replacement. |

## Adding New Work

### Add a new UI component

1. Create it under `src/frontend/components`.
2. Keep browser-only state in client components with `"use client"`.
3. Import shared UI primitives from `src/frontend/components/ui`.
4. Import class helpers from `@/frontend/utils/cn`.

### Add a new frontend tool listing

1. Add catalog metadata in `src/frontend/constants/tools.ts`.
2. Add expanded metadata in `src/frontend/data/expanded-tools.ts` if it needs `/tools/[slug]/[tool]`.
3. Add workspace UI under `src/frontend/components`.
4. Keep route files in `src/app` as route shells only.

### Add a new API endpoint

1. Add a thin route in `src/app/api/.../route.ts`.
2. Add a controller in `src/backend/controllers/...`.
3. Add validation in `src/backend/validators/...`.
4. Add business logic in `src/backend/services/...` or `src/backend/tools/...`.
5. Return responses through `src/backend/utils/response.ts` or shared API helpers.

### Add a new PDF endpoint

1. Add route file under `src/app/api/pdf/<tool>/route.ts`.
2. Add controller under `src/backend/controllers/pdf/<tool>.controller.ts`.
3. Reuse `handlePDFRequest` from `src/backend/utils/pdf-request.ts`.
4. Reuse upload helpers from `src/backend/lib/upload.ts`.
5. Add or reuse schema parsing in `src/backend/validators/pdf.validator.ts`.
6. Put PDF manipulation in `src/backend/services/pdf/<tool>.service.ts`.

### Add a new dynamic calculation/conversion tool

1. Add config/runner support in `src/backend/tools/calculation-tools.ts`.
2. Add a folder under `src/backend/tools/calculators` or `src/backend/tools/conversion`.
3. Add `types.ts`, `validator.ts`, `service.ts`, and `route.ts` if the tool needs a standalone module.
4. Add frontend catalog metadata in `src/frontend/constants/tools.ts`.

## Verification Checklist

Run after structural or feature changes:

```bash
npm.cmd run typecheck
npm.cmd run build
npm.cmd run dev -- --port 3005
```

Then verify:

- `/` loads.
- `/api/health` returns `{ "success": true, "message": "Backend Running" }`.
- No route handler contains business logic.
- No frontend component imports from old top-level paths like `@/components`, `@/services`, or `@/validators`.
- No `console.log`, `TODO`, or `FIXME` remains in committed source unless deliberately justified.
